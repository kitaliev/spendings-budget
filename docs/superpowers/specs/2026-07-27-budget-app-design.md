# Бюджет на день — дизайн

Дата: 2026-07-27
Статус: одобрено (визуальный дизайн + функциональная спецификация), ожидает ревью документа перед планом реализации.

## 1. Что это

PWA для учёта личных расходов, построенное вокруг одной идеи — **дневной бюджет**: фиксированная сумма в день, которая копится, если её не тратить, и уходит в минус при перерасходе. Плюс независимый раздел учёта долгов. Только iPhone, никогда не открывается на ПК.

Визуальный дизайн (кликабельный прототип, 4 экрана): https://claude.ai/code/artifact/84111cb8-abd6-4ebc-95a8-9d17a5427f02

## 2. Установка и распространение

- Без публичного домена. Свой сервер, доступ по IP.
- Сертификат Let's Encrypt на голый IP (GA с января 2026, профиль `shortlived`, ~160 часов / ~6.5 суток). Требует ежедневного автопродления (cron/systemd timer) и алерта при сбое рендера — окно на исправление намного короче, чем у обычных 90-дневных сертификатов.
- Установка: один раз открыть `https://<ip-сервера>/` в мобильном Safari на iPhone → «На экран Домой». После установки сервис-воркер обслуживает приложение из кэша — постоянная доступность сервера для работы приложения не требуется.

## 3. Архитектура и хранение данных

- **Источник истины — телефон.** IndexedDB на устройстве, приложение полностью работает офлайн бессрочно, без сервера.
- **Сервер — только бэкап**, не рантайм-зависимость. Держит SQLite.
- **Синхронизация**: при наличии сети и доступности сервера телефон отправляет полный JSON-снимок своего состояния на сервер. Сервер перезаписывает свой SQLite целиком из этого снимка (данных мало — простая перезапись надёжнее и проще инкрементального diff'а).
- Сервер хранит на своём диске ротацию из нескольких последних версий SQLite (последние N дней) — защита от случая «плохая синхронизация затёрла хорошую копию» теперь, когда внешнего дубля (iCloud и т.п.) в схеме нет — этот вариант обсуждался и был сознательно отклонён: один VPS без внешней копии остаётся единой точкой отказа, риск принят пользователем осознанно.
- **Восстановление**: если при запуске локальная база пуста — предложение в один тап подтянуть последний бэкап с сервера (не автоматически, чтобы не перезаписать молча пустое-но-осознанное состояние).

## 4. Авторизация

- Один пользователь, без мультитенантности.
- Пароль + серверная сессия. Домена нет → WebAuthn/Passkeys и Sign in with Apple технически недоступны (оба жёстко требуют настоящий регистрируемый домен, IP не поддерживается ни тем, ни другим — подтверждено).
- Safari сам предложит сохранить пароль в iCloud Keychain; автозаполнение сохранённого пароля разблокируется Face ID на уровне ОС — даёт ощущение входа по Face ID без WebAuthn и без домена.

## 5. Технологический стек

Vue 3, **Options API** (не Composition API), **без TypeScript**. **SCSS** + **БЭМ**-нотация. **Без Tailwind** ни в каком виде. Mobile-only, адаптив под десктоп не нужен.

## 6. Модель данных (сущности)

- **Transaction** — сумма, дата, category_id, отметки создания/редактирования.
- **Category** — название, эмодзи, parent_id (nullable → бесконечная вложенность), archived (bool), может быть жёстко удалена.
- **DailyBudgetRate** — сумма ставки + дата, с которой она действует (история ставок, а не одно число).
- **Debt** — название, исходная сумма, комментарий, направление (мне должны / я должен).
- **DebtPayment** — debt_id, сумма, дата.

## 7. Логика дневного бюджета

```
доступно_сегодня =
    Σ(дневная_ставка_i × дней_в_её_сегменте, по сегментам ставок месяца до сегодня)
    − Σ(все транзакции этого месяца, по дату, включительно по сегодня)
```

- Трата, внесённая задним числом, **пересчитывает текущий остаток глобально** — не изолирована в «корзину» своего дня.
- Месяц стартует с нуля 1-го числа — остаток или минус прошлого месяца не переносится.
- Смена дневной ставки в Настройках действует **только вперёд**, с момента изменения — уже прожитые дни месяца сохраняют прежнюю ставку (отсюда таблица истории ставок, а не одно поле).
- Никакого дохода/возврата в v1 — единственный приток денег в бюджет это дневная ставка. Ошибочную трату исправляют редактированием/удалением транзакции, а не встречной записью.

## 8. Модалка добавления расхода

Открывается автоматически при каждом запуске приложения поверх дашборда; также доступна по кнопке «+» в таббаре.

- Сумма вводится только экранным калькулятором: цифры, запятая, `+ − × ÷` (математический приоритет — `×`/`÷` считаются раньше `+`/`−`), стирание. Системная клавиатура никогда не появляется.
- Дата: «Сегодня» (по умолчанию) / «Вчера» / «Другая дата» — открывает нативный iOS-пикер дат.
- Категория: эмодзи + название, бесконечная вложенность. Тап по категории с подкатегориями показывает список подкатегорий вместо текущего (с строкой «‹ Назад» в том же списке). Тап по категории-листу фиксирует введённую сумму как транзакцию с выбранной датой.
- Закрытие без ввода: свайп вниз или кнопка «×» — тап по затемнённому фону не закрывает (чтобы случайно не потерять введённую сумму).
- То же окно переиспользуется для редактирования существующей транзакции (с предзаполненными полями) и получает дополнительную кнопку «Удалить».

## 9. Категории (Настройки)

- При первом запуске создаётся ровно одна дефолтная категория — «💰 Расход» — чтобы приложением можно было пользоваться сразу.
- **Архивация** — скрывает категорию из пикера в модалке, не трогает исторические данные и бюджет; архивация родителя архивирует всё поддерево.
- **Удаление** — отдельное, деструктивное действие с дополнительным подтверждением; каскадно удаляет все транзакции категории.

## 10. Дашборд (вкладка «Бюджет»)

- Навигация по месяцам сверху.
- Главная цифра: для текущего месяца — живой остаток «на сейчас»; для прошлых месяцев подпись меняется на «Остаток на конец месяца» и показывает финальный остаток того месяца. Отрицательное значение — отдельным цветом (см. §12).
- Общий расход за просматриваемый месяц.
- Столбчатая диаграмма по 12 месяцам, без цифр (чисто визуальное сравнение высоты) — год в диаграмме соответствует году просматриваемого месяца (перелистывание через границу года переключает и диаграмму).
- Pie chart расходов по категориям за месяц (без цифр на самой диаграмме, суммы — в списке-легенде под ней) с drill-down: тап по категории с подкатегориями показывает разбивку по ним же (pie + легенда), с возможностью вернуться назад.

## 11. Навигационная оболочка

Нижний таб-бар с двумя вкладками — «Бюджет» и «Долги». Настройки — не таб, а иконка-шестерёнка в углу. Кнопка «+» (FAB) повторно открывает модалку добавления расхода.

## 12. Долги (вкладка «Долги»)

- Сегментированный переключатель «Мне должны» / «Я должен».
- Долг: название, исходная сумма, комментарий.
- «Оплатить» создаёт запись в истории платежей долга (дата + сумма) — не просто уменьшает одно число. Остаток = исходная сумма − Σ платежей. Тот же паттерн append-only-истории, что и у транзакций бюджета.
- Долг с остатком 0 уходит в свёрнутый список «Закрытые», не удаляется.
- **Полностью независимо от дневного бюджета** — ни один платёж по долгу не создаёт транзакцию и никак не влияет на бюджет, расход месяца или pie chart.

## 13. Визуальный язык

Обе темы (светлая/тёмная) полностью проработаны токенами — см. прототип. Нейтральный тёмно-бирюзовый фон (не чёрный и не тёплый крем), один акцент — приглушённое золото/латунь. Кирпично-красный зарезервирован только под состояние «минус по бюджету» — больше нигде не используется, чтобы не путать с обычными категориями. Денежные суммы и калькулятор — моноширинным шрифтом (SF Mono), остальной интерфейс — системным (SF Pro). Палитра категорий pie chart проверена скриптом на цветовую слепоту (CVD).

## 14. Явно вне рамок v1

- Доход/возврат как отдельная операция (только дневная ставка как приток).
- Мультипользовательский режим.
- Десктопная/адаптивная раскладка.
- Внешний облачный бэкап (iCloud) — рассматривался, отклонён в пользу единственной серверной копии.

## 15. Рекомендация по очерёдности реализации

Клиент (IndexedDB, полностью офлайн) самодостаточен и уже закрывает большую часть исходного запроса — «работает без интернета, хранит всё локально» — без сервера вообще. Только пункт «ничего не пропадёт при переустановке» требует серверной части. Предлагаю два независимых плана реализации, не один общий:

1. **Фаза 1 — автономное приложение**: Vue-фронтенд, IndexedDB, сервис-воркер, весь функционал бюджета и долгов. Полностью рабочий, устанавливаемый продукт уже на этом этапе.
2. **Фаза 2 — сервер и синхронизация**: VPS, сертификат на IP, авторизация, приём бэкапов, восстановление.

Так первая же фаза даёт готовым к использованию продукт, а не полуготовую связку фронтенда с недостроенным бэкендом.
